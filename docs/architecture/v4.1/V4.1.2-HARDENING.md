# V4.1.2 production-authority hardening closure

Base: `d231942c92592ecc05771966089aa44f1ba4ea5e` (V4.1.1).
Scope: executable architecture kernel only. Production Reach and existing runtime authority are intentionally untouched.

V4.1.2 changes the proof obligation from “safe when well-formed data is passed to the right helper” to “forged, stale, partial, reordered, or contradictory input cannot acquire runtime authority through the public kernel API.”

## Canonical authority surface

The only state-changing production-facing primitive is:

```text
applyKernelCommand(KernelState, KernelCommand)
  -> KernelResult { state, events }
```

`architecture/v4.1/model.ts` is only a compatibility re-export of `kernel.ts`. V4.1.1's independent lease/lifecycle/effect helper implementation is gone from the V4.1.2 public surface.

Kernel-owned state contains world/generation/time/revisions, immutable contract store, ATR lifecycle state, resource leases, effect commits and usage, accepted verifier facts, witness proofs, preemption transactions, Mission frontier, APPEND stores, budget ledgers, and journal sequence state.

## Additional counterexamples found during the five review passes

The V4.1.2 work uncovered issues beyond the supplied blockers:

1. budget/deadline enforcement could have force-revoked a bounded non-preemptible lease;
2. ordinary `ACTIVE -> OBSERVING/BLOCKED` pause could have bypassed safe-yield;
3. VERIFY and Mission supersession could have terminalized through the same unsafe path;
4. audit replay could have returned a live branded state after replay bypassed source capabilities;
5. witness revision was stored but not advanced when a witness proof was accepted;
6. one verifier snapshot could contain contradictory duplicate values for one predicate;
7. a stale preemption transaction could continue contributing inherited priority;
8. multiple bounded conflicting leases used the latest hard deadline rather than the earliest one.
9. VERIFY could be invoked without a verifier capability and causal credit was caller-asserted;
10. a preemption victim could ACK safe yield and then issue new work before commit;
11. lower scheduling classes could overtake higher classes through fairness aging;
12. explicit urgency existed in prose but not in the canonical executable contract;
13. effect reconciliation accepted unrelated current verifier facts with no commit-level causal binding;
14. Jev frames omitted live effect/progress state and admission did not re-derive the live projection.

These are now explicit regression cases or invariant checks.

## Five review passes

### 1. Authority / capability

Contract registration, verifier facts/VERIFY, witness proofs, progress evaluation, Mission updates, scheduler actions, controller debit/effect/append operations, dispatch, world/runtime boundary changes, and live journal recovery have distinct runtime-branded capabilities. Plain structural objects do not pass the corresponding check. Controller capability identity includes transition id, contract hash, and generation.

This is an architecture capability boundary, not a claim that TypeScript modules form a security sandbox. Production packaging must prevent semantic code from importing `kernel-internal/*`; that remains a migration gate.

### 2. State machine / concurrency

The reducer owns lifecycle, leases, tokens, preemption and registry revision atomically. Multi-victim preemption does no partial suspension. Every bounded non-preemptible path that can leave ACTIVE requires safe yield except a true world/runtime discontinuity, where old authority is invalid by definition.

### 3. Control / liveness

Late yield preserves violation evidence without dead-ending recovery. A yielded preemption victim cannot start new effects/debits/APPEND work before atomic commit. Priority inheritance affects executable scheduling selection. Scheduling class bands are strict; bounded urgency, fairness aging, and deadline tie-breaking operate inside the class. BLOCKED work does not age. Equal-priority churn is residency-gated. Wall deadline continues while suspended; active time accrues only ACTIVE time.

### 4. Crash / replay

Effect dispatch has an explicit linearization point. A crash after dispatch but before world evidence is `UNKNOWN`, not “did not happen.” Definite reconciliation requires current trusted fact ids causally bound to the exact effect commit. Audit replay is non-authoritative. Trusted restart recovery replays the exact journal and then rebrands only after invariant validation.

### 5. Minecraft adapter

The repository mutation inventory found hidden/coupled Mineflayer surfaces including pathfinder/control state, implicit look during placement, window withdrawal raw writes, collectblock-driven locomotion, raw movement packet/pose mutation, and direct executor calls not covered by ActuationPort. These are documented in `RESOURCE-AUTHORITY-INVENTORY.md` and are production gates, not assumed solved by the pure kernel.

## Deliberate non-claims

V4.1.2 does not prove the existing Mineflayer adapter declares every hidden physical resource. It does not provide exactly-once Minecraft side effects. It does not make module-private capability factories cryptographically inaccessible. It does not prove server rollback/reconnect identity policy. It does not enable VTR authority in production Reach.


## Jev usage audit

Jev examples were searched again before finalizing V4.1.2. The repository harness uses bounded typed `choice`, boolean/termination-style, and score questions with request identity/stale fencing and batch evaluation. Public Vercel AI / TypeSafe examples use `experimental_evaluate` with one structured `state` and typed `questions` (Choice, Score, Boolean). V4.1.2 therefore keeps Jev as a typed proposal plane and performs world/binding/candidate/lease authority checks entirely in deterministic kernel code.

### Jev live projection

The decision frame now includes live effect state and transition progress records in addition to lifecycle/resources/facts/witnesses/budgets/Mission/Viability. Admission re-derives the frame from live KernelState after identity fences; an old frame is rejected even when fact/registry/Mission binding and scheduler epoch did not change. Progress records require a registered contract-bound `PROGRESS` evaluator capability and monotonic revision/time.
